Settings reference

What every configuration field in this app actually does and where it's used — read-only documentation, no inputs here.

Live Test tab

ProtocolD2E (Direct-to-Engine) or A2A. D2E only works against Standard-harness Copilot Studio agents — GitHub Copilot harness agents reject it outright with a canned refusal. A2A exists specifically to reach GitHub Copilot harness agents; it is required for those agents.
Endpoint URL / Host / Schema / Environment IDThe D2E conversation endpoint (or A2A agent URL) you paste; host/schema/environment_id are auto-derived from it. Identifies which agent and environment a run targets.
Dataverse org URL (org_url)The environment's Dataverse URL (e.g. https://orgxxxx.crm.dynamics.com). Used only for the History tab's transcript-enrichment check (reading conversationtranscript records).
Auth modeHow the tool signs in: device code (one account), account pool (multiple accounts via wizard), static bearer token (paste one, no sign-in), or A2A confidential client (tenant_id/client_id + client_secret, no interactive sign-in).
Tenant ID / Client IDThe Entra tenant and app registration used for sign-in and for Dataverse/credit lookups tied to this run.
Static token / Client secretOnly used by the matching auth mode; never persisted into saved presets or auth profiles.
Mode: smoke / stepped / spikeSmoke fires a handful of sessions once, for a quick end-to-end sanity check. Event spike ramps virtual users up, holds, then ramps down. Stepped RPM holds a sequence of target request rates to characterize throughput limits.
Mode parametersSmoke: sessions to run. Spike: virtual users, sessions/VU, ramp-up/hold/ramp-down seconds. Stepped: comma-separated RPM steps, hold-each seconds, max concurrency.
Turns / sessionHow many conversation turns each virtual session sends before ending.
Think time (min/max)Randomized pause between turns within a session, to emulate realistic user pacing instead of hammering the agent with back-to-back requests.
Request timeoutPer-request timeout (seconds) before a call is treated as failed.
Prompts / prompt orderThe question pool sent to the agent. "Random pool" samples a random line per turn; "Sequential script" uses line 1 for turn 1, line 2 for turn 2, etc.
Conversation mode: Scripted sessionsAlternative to the shared prompt pool above -- define several full multi-turn scripts (each its own ordered list of turn prompts, any length). Each session runs ONE whole script, picked at random, start to finish; "Turns / session" doesn't apply in this mode since turn count comes from the chosen script. Scripts can be typed by hand or imported from a Copilot Studio test-case CSV export (Test Case ID, Turn, Query). Has its own "Edit scripts" library, separate from question sets.

Accounts tab

Pool (auth profile)A named (tenant_id, client_id, auth_mode) combo you can switch between without retyping GUIDs — independent of saved load-test presets.
Device-code sign-inEach "Add account" click opens a fresh interactive device-code flow (open a URL, enter a short code) so you can add one more real signed-in identity to a pool, for simulating multiple concurrent users.
Enable / disablePer-account toggle to exclude a cached account from being used in the next run without removing it from the cache — re-enable any time.

History tab — enrichment sources

Live (SSE)Counted in real time from the agent's streamed plan events during the run. Fastest, but best-effort — it only recognizes the Standard-harness "taskDialogId" tool-call marker, so GitHub Copilot harness agents (reached via A2A) always show 0 here even when they made real tool calls.
Transcript (Dataverse)Authoritative tool/connector/action counts parsed from the environment's conversationtranscript records, keyed by conversation_id. Typically lags ~30-35 min after a conversation starts — "Re-check transcripts" queries on demand.
Application InsightsGenAI OpenTelemetry spans (tool name, success/fail, duration) queried from the linked Log Analytics workspace, correlated by conversation_id. Usually available ~1-2 min after a conversation ends — the fastest authoritative source, and the only one that reports per-tool success rate and error messages.
Why they can disagreeLive undercounts for GitHub Copilot harness agents (a different signal format than transcripts/App Insights use). Transcripts and App Insights can disagree in absolute counts because they key off different event granularities (per-invocation vs per-operation), and App Insights has nothing to show if the agent isn't wired to this specific resource. Prefer App Insights or transcripts over Live for final reporting — Live is only a quick in-flight signal.

Settings tab

Application Insights resourceThe Azure Application Insights resource (and its linked Log Analytics workspace) that the App Insights enrichment source queries. Configure it once here — every run's "Check App Insights" button reuses it.

Manage question sets

Save reusable lists of prompts (e.g. "SOP questions", "weather smoke test") so you don't have to retype them every time — independent of your load-test presets.

Edit scripts

Each session runs ONE whole script, picked at random, start to finish. Scripts can have different numbers of turns -- each session's turn count is simply whatever its chosen script has.

Accepts two export formats: the new-harness test-case export -- one row per TURN, with columns Test Case ID, Turn, Query -- or the Standard-harness (GeneralQuality) eval export, with leading # metadata lines then columns conversationNumber, question, response (turn order inferred from row order per conversation). Any Expected Response/response column is ignored. Rows are grouped by test case/conversation id to rebuild each script. Importing replaces the scripts below.
